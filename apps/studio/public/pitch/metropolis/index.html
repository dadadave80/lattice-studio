Lattice Studio

The design environment for EIP-2535 diamonds. Compose a contract system from facets, catch every mistake on the edit that makes it, deploy to Monad in one transaction, and prove what's running with a passport anyone can recompute.

Open the app github.com/dadadave80/lattice-studio

The problem

A diamond's mistakes show up at deploy time, or in the audit

  • Selector collisions

    Two facets claim the same function. One silently wins.

  • Init order

    An init runs before the module it depends on is set up.

  • Storage overlap

    Two facets write to the same namespace.

  • Authority

    Nobody, or the wrong key, ends up able to upgrade.

A diamond is one address made of many facets: no 24 KB limit on the whole, upgradeable piece by piece. It is also the easiest contract system to get wrong, and on Monad a reverted deploy still pays its whole gas limit.

What it does

Every check runs on every edit

  • Place facets from the Lattice catalog on a sheet: 105 facets, 90 inits, 85 recipe templates.
  • Nine families of checks rerun on each change, in about 2 ms for a 30-facet diamond. Each finding names its fix.
  • Deploy through LatticeFactory in one transaction, to an address Studio predicted first. The on-chain loupe is compared with the plan, then the source is verified.
  • No backend, no accounts, no analytics. Works offline after the first load.

Lattice Passport

Eight claims about a deployed diamond, and a digest anyone can recompute

  • PP-01

    Code is deployed at the address.

  • PP-02

    It answers the EIP-2535 loupe.

  • PP-03

    Every routed facet's code hash matches a known Lattice release.

  • PP-04

    Selector routing matches the plan from the recipe.

  • PP-05

    The recipe uses a bundled catalog.

  • PP-06

    No DiamondCut since deployment.

  • PP-07

    The earliest cut identifies the deployment path.

  • PP-08

    Who owner() says holds the diamond.

lattice-studio passport 0x0072…5c7B --chain 10143 --recipe governed-vault.recipe.json --json. Exit codes make it a CI gate. It says what it can't prove too: storage values, the safety of unaudited code, or an honest RPC.

Agents you can check

Agent trust from checks a person can rerun, not from the agent's word

  • Lattice Drafter

    Drafts a recipe from plain English by calling Studio's CLI as tools. It may finish only when check exits 0. It never deploys and never signs.

  • ERC-8004

    The Drafter's registration file, and the commands that register it on Monad testnet and credit it from passports with no failed claim, are in the repo.

  • A skill for any agent

    Claude Code, Codex and the rest drive the same CLI through a skill file: stable JSON, stable exit codes, the same analysis as the sheet.

The person stays in the loop at the one step that matters: confirming the authority address and signing the deploy.

Why Monad

Built for how Monad charges, settles and remembers

  • Canonical deployers

    CreateX and Arachnid's proxy are live on Monad, so Lattice's shared contracts land at the same predicted addresses as on every other chain.

  • Gas charged in full

    Monad bills the whole gas limit, even on a revert, under a 30M cap per transaction. Catching a bad deploy before signing saves real MON. Studio enforces the cap.

  • Sub-second finality

    Blocks every few hundred milliseconds, final two blocks later: check, deploy and passport in one sitting.

  • History at scale

    A diamond's cut history can sit anywhere in tens of millions of blocks. The passport reads it through Envio HyperRPC in one query.

Monad's node refuses eth_simulateV1 as most clients send it, so Studio's deploy simulation falls back to eth_call. Sourcify verification goes through BlockVision's Monad instance; Monadscan is verified through Etherscan's API V2.

One core, three surfaces

  • CLI

    check recipe.json --json and passport <address>, with stable exit codes for pipelines.

How it's built

A pure core, a generated catalog, and tests at every layer

  • 3,700+

    unit tests

  • 1,600+

    component tests in a real browser

  • 480+

    end-to-end flows

  • 1,100+

Bun monorepo. The core has no DOM, network, clock or randomness. The catalog is generated from a pinned Lattice checkout. React and React Flow for the sheet; viem and wagmi in a lazily loaded chain module, the only code that talks to a network. Golden tests run against Lattice's own deploy scripts; chain tests run on Anvil.

Status and next

What's real, what isn't yet, and where it goes

  • Real today

    Compose, check, export, deploy and passport new Lattice diamonds on Monad Testnet, Sepolia, Base Sepolia, HSKChain Testnet, Hedera Testnet and Avalanche Fuji. All of Studio was built between September 23 and October 13, 2026.

  • Provisional

    The catalog is built from Lattice commit 6c8db45, not a tagged release. Mainnet is off until Lattice is audited. The CLI is not on npm yet. The Drafter is registered under ERC-8004 by command, not yet on chain.

  • Next: upgrades of live diamonds, the CLI on npm, the re-pin to Lattice's tagged release, Monad mainnet.
